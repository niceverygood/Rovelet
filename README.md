# Rovelet

개발 중인 움직이는 성 3D 액션 게임의 소스 저장소입니다. 게임 내 명칭은 기존 이름을 유지하고 있습니다.

## 소스에서 실행

Node.js 22.12 이상을 설치한 뒤 실행하세요.

```sh
npm install
npm run dev
```

프로덕션 빌드: `npm run build` · 빌드 미리보기: `npm run preview` · 전체 테스트: `npm test`

이 저장소는 원본 프로젝트의 최신 작업 파일을 정리한 첫 공개용 스냅샷입니다. 이전 Git 이력, 로컬 QA 기록·스크린샷, 실제 서명/빌드 입력, 개인 경로를 사용하는 임시 도구, 설치된 의존성, 배포 ZIP/APK/AAB는 포함하지 않습니다. 아래 기존 문서의 검증 파일 링크는 원본 로컬 프로젝트를 가리키며 이 저장소에는 없을 수 있습니다. `start-game.cmd`는 별도 빌드된 실행 패키지용입니다. 스토어 출시 준비 완료 상태가 아니며 `releaseReady=false`를 유지합니다.

# 작은 성의 큰 여행 · Wandering Hearth

검증 자료 안내: 이 문서의 `verification/` 경로와 `performance-*.json`, 개발 기록 링크는 원본 프로젝트 폴더를 기준으로 합니다. 실행 ZIP에는 QA 보고서·스크린샷·개발 기록을 별도로 포함하지 않으므로, 검증 자료는 원본 프로젝트의 같은 경로에서 확인하세요.

무드보드의 작은 바퀴 성으로 여행하는3D 액션 로그라이트입니다. 웹 버전은1.0.0-rc.1이며 상용 출시 완료 상태가 아닙니다. 현재 소스는69파일, Meshy14자산(이미지 기반12+텍스트 기반2)/런타임14와71바이너리 지문,30무기·15판·전투3지역과 마을3풍경을 포함합니다. g 고지와 tint source442를 반영한 ROOT79680b8 항목은 전체1013·집중38 PASS, 실제 after-only34.992초/raw6·full6/오류·경고0을 확인했습니다. limitedTintAccepted:true는 색상 표현만의 제한 승인이고 small/full-plume 가독성과 c.3/parent damage는OPEN입니다. 현재 unsigned native 빌드·출력 검증은 완료했고 최신 정상 실시간15판 완료는0이며 FPS·물리 OS/기기·권리·서명·스토어 계정·운영자/공개URL은 미확인입니다. releaseReady=false이며 정확한 상태는 RELEASE_STATUS.json을 따릅니다.

## 실행

로컬 플레이 패키지의 `start-game.cmd`를 더블클릭하세요. Node.js 22.12 이상이 필요하며 이 PC의 Codex 번들 Node도 자동 탐색합니다. 별도 npm 설치 없이 빌드된 게임을 실행합니다. 터미널에서는 `node server.mjs` 후 `http://127.0.0.1:4180/`에 접속합니다. HTML을 직접 열면 3D 파일을 불러올 수 없습니다.

이미 같은 빌드가 실행 중이면 재사용하고, 포트가 다른 프로그램에 사용 중이면4181~4190을 탐색합니다. **주소/포트가 바뀌면 브라우저 저장 공간도 달라집니다.** 기존 저장을 유지하려면 이전 서버를 종료하고 같은 주소에서 새 빌드를 실행하세요. 게임 화면에서 저장·귀환을 마친 후 업데이트하세요.

## 플레이

- PC: W/S 또는 ↑/↓ 전진·제동·후진, A/D 또는 ←/→ 조향. 회전에는 이동이 필요합니다.
- 모바일: 왼쪽 조이스틱을 드래그해 이동·조향. 놓으면 감속합니다.
- Space/오른쪽 증기 버튼: 가속. 1/방패: 방어막. 2/공구: 수리. ESC/상단Ⅱ: 일시정지.
- 무기는 사거리 안에서 자동 발사합니다. 기본 대포는 포신 조준 범위에 적이 들어오도록 성의 앞을 맞춰 주세요.
- 파란 다이아를 수집해 레벨을 올리고 무기·회복·성 성장을 선택합니다. 성은3단계, 기본 슬롯은2→4→6이며 정비소로 최대8개가 됩니다.
- 초원·화산·빙하 각5판, 총15판입니다. 각 판의 중간 수호자를 처치한 뒤 최종 수호자를 물리치면 다음 판이 열립니다.
- 15판을 완주하면 타이틀과 마을에서 엔딩을 다시 볼 수 있습니다. 크레딧·뒤로가기·마을 복귀는 진행 중인 탐험과 보상을 변경하지 않습니다.
- 정비소는 체력·속도·수리·슬롯, 대장간은 피해·발사 간격, 온실은 회복·금화·방어막과 연동됩니다. 시설은6단계이며 **다음 출격부터** 적용됩니다.
- 마을 지도에서 시설을 고르거나 건설 위치를 선택·회전·무료 이동할 수 있습니다. 주민9명이 마을을 돌아다닙니다. 초원·화산·빙하 마을풍경은 캠페인1/6/11 진척에 따라 선택되며 시설·주민·공사·재화·저장을 공유합니다.
- 건설 위치를 고른 뒤 방향키로 미세 이동, R로 회전, Enter로 확정, ESC로 취소합니다. 버튼에 초점이 있으면 Enter/Space는 해당 버튼을 실행합니다.
- 무기 도감에서30종을 실제3D로 시연합니다. 설정에는 한/영, 전체/BGM/SFX음량, 움직임 줄이기, 대비, 지원 기기 진동이 있습니다.

## 저장과 복구

브라우저 localStorage에 마을과 탐험을 저장합니다. 탐험은10초 간격, 탭 숨김, 저장 후 타이틀, 페이지 종료 때 저장합니다. 정상 저장을 백업하고 손상 시 복구합니다. 보상은 정산 저널을 이용해 중복 지급을 막습니다. 저장 공간이 부족하면 결과 화면의 재시도 버튼을 사용하세요. 브라우저 데이터 삭제·시크릿 모드 종료·다른 주소 접속은 저장 손실을 일으킬 수 있습니다.

## 개발·빌드

검증 환경: Node24.19 / pnpm11.25 / Three0.186.1 / Vite8.3.4. 의존성은 버전과 잠금 파일로 고정합니다.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm build
node server.mjs
```

`pnpm dev`는 개발 서버, `pnpm balance`는 고정 시드 수치 모델입니다. 모델의 완료 결과는 실제 조향·피격 난이도 검증을 대체하지 않습니다. 테스트용 `window.__hearth`와 무드보드 비교 버튼은 개발 빌드에만 있습니다.

## 배포 패키지

```powershell
pnpm release
# 출력 위치를 지정할 때
node scripts/release.mjs --out .. --work ../../work/release
```

전체 테스트→프로덕션 빌드→개발 훅/키 검사→Brotli/Gzip→웹 ZIP/로컬 실행 ZIP과 SHA256 매니페스트를 생성합니다. 웹 ZIP의 루트에는 `index.html`이 있습니다. HTTPS 정적 호스팅 또는 HTML5 게임을 지원하는 웹 스토어에 파일 구조 그대로 업로드하세요. 상대 경로를 사용하므로 하위 폴더에서도 작동합니다. 직접 호스팅하는 서버의 하위 경로 검증은 `GAME_BASE=/hearth/`와 `PORT`를 설정해 할 수 있습니다.

Steam 실행 파일·Google Play/App Store 패키지·서명·계정·심사·결제는 이 웹 패키지에 포함되지 않습니다. 공개 게시 전 `RELEASE_STATUS.json`의 차단 사항과 `LICENSES.md`를 확인하세요. 배포 승인이나 스토어 제출은 자동으로 실행하지 않습니다.

## 에셋·음향·현재 제한

Meshy 원본14개와 검증된 runtime14개를 사용합니다. 성·적 탑·나무·폐허·집·대장간·온실·대포·벌집·발리스타의12개는 이미지 기반이며, 별도 발사체·충돌 파편2개는 텍스트 기반입니다. 개별 출처·수정은 LICENSES.md/ASSET_DELIVERY.md를 따르며 권리를 승인한 뜻은 아닙니다. asset-provenance.json의 실제14자산 생성 기록 합계는240크레딧입니다(이미지 기반12개180 + 이후 텍스트 기반2개60). 이번 문서 정리와 warm-tint 변경의 신규 생성 비용은0입니다. 이는 생성 플랜·참조 이미지·배포 권리 승인과 별개입니다. 실행 중 API나 키가 필요하지 않습니다. 새 무기·발사체·지형·주민·효과는 코드로 구성했습니다. 평면 무드보드와 실시간3D의 형태·광원은 차이가 있으며100% 일치를 주장하지 않습니다.

## 배포 복구

이전 빌드 ZIP과 릴리스 매니페스트를 보관하세요. 문제 발생 시 서버를 멈추고 이전 `dist`를 복원한 뒤 같은 주소에서 실행합니다. 브라우저 저장 데이터는 지우지 마세요. 저장 키 `wandering-hearth:v1`과 schemaVersion2는 이전 옵션을 보정하며 유지됩니다. 버전이 다른 서버가 동시에 실행되면 실제 접속 주소와 `/health`의 버전을 먼저 확인하세요.

로컬실행스크립트는127.0.0.1의루트주소를명시하고건강한자식프로세스의실제listener·버전·빌드·basePath를확인합니다. `.hearth-server.json`은실행PID/생성시각/절대서버경로를기록하는로컬운영파일입니다. 주소가달라지면브라우저저장소도달라지므로기존주소를유지하세요. 이미열린탭은서버를바꿔도기존JS를사용하므로새코드는정상저장후다시열때적용됩니다.

## 과거 가속 캠페인 회귀 검증 — 최신 정상15판 증거 아님

`node scripts/qa-server.mjs`로 파일 감시 없는 별도 개발 검증 서버를 열고, `node scripts/verify-campaign.cjs`를 실행합니다. 개발 의존성 playwright-core와 설치된 Edge를 사용하며 필요하면 PLAYWRIGHT_MODULE을 지정하세요. GAME_QA_URL은 사용자 저장소 보호를 위해 `http://127.0.0.1:4176/`만 허용합니다. 실행별 report/획득저장/스크린샷은 verification/campaign의 새 폴더에, 작업 로그는 상위 work에 남깁니다. 소스 SHA·기준 커밋·미커밋 상태와 독립 보상/시설 구매 원장을 기록하며 이전 증거를 덮어쓰지 않습니다. 이 스크립트는 출시 빌드에 포함되지 않습니다. 실제30Hz 물리 틱을 모두 계산하고 렌더링만 샘플링하므로 실시간FPS 측정이나 사람 체감 난이도의 증거는 아닙니다. RNG 시드는 고정하지만 첫 장면의 렌더 캐시 상태까지 완전 결정적으로 초기화하지는 않습니다.

## 배포 텍스처 준비
public/models의원본14개(이미지12+텍스트2)는보존하며, runtime-models의검증된배포용파일만프로덕션dist/models에복사합니다. 일반 pnpm build는브라우저나Meshy API없이캐시의원본SHA/텍스처정책/모든기하바이트를검증합니다. 원본이나texture-policy를변경한경우 pnpm assets:prepare로다시생성하세요. 생성도구는개발전용playwright-core1.62.1과설치된Microsoft Edge를사용하며, 다른설치된Chromium은 BROWSER_CHANNEL=chrome 등으로지정할수있습니다. 브라우저설치파일은실행ZIP에포함되지않습니다. 런타임과같은Canvas축소→무손실PNG→재디코드RGBA검사이며, JPEG재압축/기하단순화는하지않습니다. dist/만빌드출력으로허용하여원본폴더덮어쓰기를방지합니다. 과거12개모델측정에서는206.45MB에서57.55MB로감소했으며, 현재14개전체의최종용량측정으로재사용하지않습니다.

## Native 전달과 현재 검증 범위
